# ローカルライブラリ

Catra が管理するデータベースと、それに対応する実体の組をローカルライブラリとする。実体は Catra の管轄ディレクトリに置き、取り込み元に対して非破壊で管理する。外部からダウンロード、ドラッグ&ドロップ、インポートされた楽曲は管轄ディレクトリへコピーする。ユーザーはパス切れを気にせず、ファイルの所在を記憶しなくてよい。

Rekordbox は第二のライブラリではない。Catra の実体を指すリンク（再生・プレイリスト・Cue 用の索引）である。正は常に Catra 側にある。

この文書は方針の確定事項と未決事項を記録する。実装手順ではない。

## 不変条件

1. 正は Catra のデータベースと管轄ディレクトリの組である。外部アプリの DB やパスを曲の同一性に使わない。
2. 取り込みはコピーである。ダウンロード、ドラッグ&ドロップ、フォルダ追加は管轄内へ複製してから登録する。元ファイルは移動も削除もしない。
3. 削除は二段階である。ライブラリから外すとゴミ箱へ移る。ゴミ箱から消すと実体を削除する。復元はゴミ箱からライブラリへ戻す。
4. Rekordbox はリンクである。Catra のファイルを `FolderPath` で指す。リンクの追加・解除は Rekordbox の Content 操作に限り、Catra の実体は触らない。

## 管轄ディレクトリ

ルートはユーザーの Music 配下とする。既定は `Music/Catra` である。Windows では `dirs::audio_dir()` 配下の `Catra` に相当する。

データベースとアートワークも同じルートに置く。バックアップ対象を一つのフォルダにまとめる。

```
Music/Catra/
  library.db
  library/{id}/{original-filename}.ext
  trash/{id}/{original-filename}.ext
  artwork/
```

配置は `一意ID / 取り込み時のファイル名` とする。タグやフォルダ階層には依存しない。パスは取り込み後に動かさない。メタデータ編集でファイルをリネームしない。同名ファイルは ID ディレクトリが分かれるため衝突しない。

変換結果は別 ID のディレクトリに置く。ファイル名は元のファイル名の stem に、変換先の拡張子を付けたものとする。

Windows で使えない文字はファイル名から置換する。ファイル名が空なら `{id}.{ext}` を使う。

ゴミ箱へ送るときは `library/{id}/` を `trash/{id}/` へ移す。相対パスの ID 以降は変えない。

- DB の `path` はルートからの相対パスとする。ルートを移しても壊れない。
- Rekordbox に渡すときだけ絶対パスに展開する。
- トラックの内部キーは安定 ID とする。内容ハッシュで同一バイトの再コピーを防ぐ。
- Catra 側に Rekordbox Content ID を保持する。ゴミ箱移動でパスが変わってもリンクを追う。

## 取り込み

入口（ダウンロード、フォルダ走査、ドラッグ&ドロップ、Rekordbox からの取り込み）は同じ手順に揃える。

1. 音声ファイルを収集する。
2. 既存判定をコピーの前に行う。同一ハッシュはダイアログなしでスキップする。タイトル・アーティスト・尺が近いがハッシュが違う場合は重複ダイアログを出す。
3. 管轄外なら管轄内へコピーする。管轄内ならコピーしない。
4. メタデータを読む。
5. DB に登録する。

コピーと DB 登録は、一時名でコピーしてから確定し、成功後に INSERT する。失敗時は一時ファイルを削除する。ライブラリに載っていない変換失敗ファイルもその場で削除してよい。

ダウンロードは最初から管轄内へ配置する。yt-dlp の出力を最終レイアウトに合わせるか、一時ディレクトリ経由にするかは実装時に決める。

### Rekordbox からの取り込み

カタログ登録ではない。実体を Catra へコピーし、既存 Content の `FolderPath` を Catra 側の絶対パスへ更新する。Content ID は維持する。Cue とプレイリストは残る。

元パスのまま登録すると、正（Catra）とリンク（Rekordbox）が割れる。パス一致だけでスキップすると、Rekordbox が元ファイルを指したまま残る。

書き込みは Rekordbox 終了中に限る（現行どおり）。

まだ Catra に入っていない Rekordbox 曲は、取り込むまで外部パスを指したままである。

## 重複

取り込み時の対話は残す。選択肢は次のとおり。

| 選択 | 候補 | 既存 |
|---|---|---|
| 既存を残す | 取り込まない | そのまま |
| 新しい方を残す | コピーして登録する | 管轄内ならゴミ箱へ送る。元ファイルは触らない |
| 別フォーマットとして取り込む | コピーして登録する | そのまま残す |

「別フォーマットとして取り込む」は、拡張子またはコーデックが違うときにだけ出す。同じフォーマット同士では出さない。

両方をライブラリに残し、同一曲のフォーマット違いとして関係づける。変換の親子とは別である。変換結果は一方から生成した派生、こちらはどちらも取り込み原盤である。片方をゴミ箱に送っても、他方は残す。

## 変換

ソースは触らない。変換結果は `library/` に置き、親トラック ID を持つ。元ファイルと派生ファイルを別の「正」にしない。

親をゴミ箱へ送るときは派生も一緒に送る。

`add_to_rekordbox` は変換結果の Catra パスを Rekordbox へリンクする操作とする。ソースの隣へ書き出さない。

## 削除

```
管轄内ファイル ──(ライブラリから外す)──► ゴミ箱 ──(削除)──► 実体消去
                      ▲                    │
                      └──── 復元 ──────────┘
```

対象は Catra が作ったコピーと変換結果だけである。取り込み元はゴミ箱にも送らない。

- 「ライブラリから外す」は DB 行削除ではない。`trashed_at` を立て、ファイルを `trash/` へ移す。
- 通常の一覧はゴミ箱以外を表示する。ゴミ箱は別ビューとする。
- 永久削除は音声、アートワーク、DB 行をまとめて消す。先に DB だけ消してファイルが残る状態を作らない。
- 重複で新しい方を残すとき、管轄内の負け側は即削除せずゴミ箱へ送る。管轄外の元ファイルは触らない。別フォーマットとして両方残すときは、どちらもゴミ箱へ送らない。
- ゴミ箱の自動削除期限は設けない。手動の「ゴミ箱を空にする」で足りる。

ユーザーがエクスプローラーで管轄内ファイルを消すとパス切れは戻る。起動時または手動の健全性チェック（相対パスの実在、ハッシュ一致）を前提とする。

## Rekordbox リンク

所属判定は、Rekordbox の `FolderPath` が Catra の絶対パスと一致すること、および Catra が保持する Content ID で行う。

Rekordbox 側の画面は残す。見ているのはリンク先の索引であり、ファイルの正ではない。

| 操作 | Catra | Rekordbox |
|---|---|---|
| 取り込み（D&D / フォルダ / ダウンロード） | コピーして登録 | 何もしない |
| Rekordbox から取り込む | コピーして登録 | 同じ Content の `FolderPath` を Catra 側へ更新する |
| Rekordbox に追加 | 変更なし | Catra の絶対パスで Content を作る |
| Rekordbox から外す | 変更なし | Content を削除する（アンリンク）。ファイルは残す |
| ゴミ箱へ | `library/` → `trash/` | `FolderPath` をゴミ箱側へ更新する（リンクと Cue を維持する） |
| ゴミ箱から戻す | `trash/` → `library/` | `FolderPath` を戻す |
| ゴミ箱から削除 | 実体と行を消す | Content も消す（パス切れを残さない） |

`rekordbox_add_content(track.path)` は、`path` が管轄内ならリンク追加として正しい。`rekordbox_delete_content` はアンリンク専用とし、Catra のゴミ箱処理と混ぜない。

## 既存データ

現行の `library.db` は外部絶対パスのカタログである。スキャンとドラッグ&ドロップは元パスを登録するだけで、実体は動かさない。ダウンロードだけが `app_data_dir/downloads` に実体を置く。変換はソースの隣に書き、ライブラリ削除は DB 行とアートワークだけで音声は消さない。

このカタログは開発中データに限る。アプリ本体には移行 UI も起動時マイグレーションも載せない。必要なときだけ `tools/` 配下の専用スクリプトで、同じ取り込みパイプライン（コピー、重複判定、相対パス化）を一括で走らせる。

新しいインストールは最初から管轄ディレクトリを正とする。

## 対象外（この段階では作らない）

- 複数ライブラリ
- 管轄ディレクトリの双方向 watch
- クラウド同期
- コンテンツアドレスストレージ
- Catra 自身のプレイリストと Cue（Rekordbox 側のリンクに残す）
- ゴミ箱の自動空化
- 同一ボリュームのハードリンク最適化
- アプリ内の既存カタログ移行

## 未決

- 管轄ルート変更 UI（既定 `Music/Catra` 以外へ移す操作）

## 確定

- ダウンロードは `{root}/incoming/download-{uuid}/` へ出力し、共通取り込みパイプラインで `library/{id}/` へ確定する。
- 内容ハッシュは xxHash64（16桁 hex、seed 0）。
